02

ReAct：讓推理與行動交錯進行

▶ 00:01:52
一句話重點

先想一步、做一步，看到結果後再想下一步。推理告訴模型該查什麼，查到的觀察又把推理拉回現實，兩者交錯就能減少幻覺。

人做事之前通常會先想，例如決定來上課，是因為想過這對自己有幫助；行動之後會看到新的狀況，再根據狀況重新思考。講者舉了個生活例子：覺得口渴，就往廚房走；到了廚房發現沒水，才根據當下情況決定下一步，也許是去超市。

ReAct 之前的兩條路各缺一半：

只有推理

Chain of thought

會列出中間步驟，但每一步都來自模型內部，沒有外部世界的 grounding。第一步的事實錯了，後面推得再合理也救不回來。

只有行動

WebGPT 這類工具互動

會呼叫瀏覽器或 API 取得資料，學的是如何操作工具與人類偏好，但不一定有完整的推理把資料串起來。

形式化：把語言空間加進動作空間

投影片用 agent 的標準設定來描述：在第 t 步，agent 看到觀察 ot，根據 context ct 選出動作 at，其中 context 就是到目前為止所有的觀察與動作。

ct = (o1, a1, …, ot−1, at−1, ot)　　動作空間：Â = A ∪ L

直接學一個 policy π(at | ct) 既複雜又昂貴。ReAct 的做法是把語言空間 L 併入動作空間 A：一個 thought 就是語言空間裡的一個動作。它有三個特性：

  • 不會改變環境，搜尋才會；
  • 幫 agent 針對目前的 context 進行推理；
  • 產生後會被加進 context，變成 ct+1 = (ct, ât)，供之後的推理與行動使用。

實作：凍結的模型加上幾個範例

原論文沒有訓練模型，而是用凍結的 PaLM 加上 few-shot prompting：在 prompt 裡放幾段人工寫好的 thought、action、observation 軌跡，再請模型產生下一步。為了確保模型輸出的動作有效，常見做法是事先列出一組合法動作，讓模型從中選擇，這等於把問題包裝成分類任務。

交錯的節奏也可以依任務調整。知識密集的問答題通常每一步都先想再做；決策類任務的步驟很多，可以讓模型自己決定這一步要思考還是直接行動。

今天的模型已經內建這個循環。講者指出，打開 Qwen 等模型的 thinking mode，思考與 tool call 交錯的流程會自動發生，因為這些模型已經在類似的軌跡上訓練過。ReAct 是最早把這件事做成有效抽象的工作之一。

04

ReAct 的實驗結果

▶ 00:17:31
一句話重點

在知識密集任務上，ReAct 不一定贏過 CoT，但和 CoT 搭配使用時效果最好；在決策任務上，它比模仿學習與 RL 的 baseline 都好，但離人類專家還很遠。

知識密集的推理任務

任務

HotpotQA 與 FEVER

HotpotQA 是建立在 Wikipedia 上的多跳問答；FEVER 是事實查核，根據 Wikipedia 判斷一則陳述是「支持」、「反駁」還是「資訊不足」。

動作空間

刻意設計得很弱

  • search[entity]：回傳該條目頁面的前 5 句，或建議 5 個相似條目
  • lookup[string]：模擬 Ctrl+F 找字串
  • finish[answer]：以答案結束

動作空間故意做得很陽春，目的是模擬人類使用 Wikipedia 的方式。比較的 baseline 有：standard prompting（沒有思考也沒有行動）、chain of thought、CoT 加上 self-consistency（取多數決，簡稱 CoT-SC），以及只行動不思考的 Act。論文另外試了兩種組合：ReAct 走不下去時改用 CoT-SC，或 CoT-SC 的多數答案不夠集中時改用 ReAct。

結果

ReAct 不是全面勝出

ReAct 通常比只行動的 Act 好；它在 FEVER 上贏過 CoT，在 HotpotQA 上則不一定。把 ReAct 與 CoT-SC 用上述方式互相備援，才能勝過其他方法。

失敗分析

錯在不同地方

CoT 的主要錯誤來源是幻覺；ReAct 接上外部知識庫，資訊比較有根據、比較可信。結論是：把模型內部知識和外部檢索結合起來，讓推理決定該去查什麼。

HotpotQA 與 FEVER 的數值表格不在本頁取得的投影片截圖中，因此這裡只寫講者口述的定性結論。

決策任務：WebShop

WebShop 是模擬的購物網站：agent 要依照使用者的指令找到並買下商品，例如「有抽屜的床頭櫃」。這裡的 baseline 是 imitation learning（IL，其實就是用人類示範做監督式微調），以及 IL 再加上 RL。Score 衡量過程中各項條件的達成程度，成功率（SR）則是完全完成指令的比例。

05

ReAct 的限制與延伸思考

▶ 00:22:00
一句話重點

ReAct 只是結合推理與行動的一種簡單做法：動作空間一大就塞不進 context，多步推理也讓推論變貴；要做出更完整的 agent，還得加上任務拆解、記憶與面對雜訊的能力。

限制一

動作空間大時放不下

動作越多，需要的示範就越多，最後放不進 context。

限制二

推論成本較高

每一步都要先產生推理，步驟一多，成本就上去。

課堂討論的三個問題

講者讓學生分組討論投影片上的問題，以下整理討論中提出的方向：

  1. 內部知識與外部檢索，什麼時候該偏重哪一邊？投影片上的第一個問題，課堂沒有展開討論。可以對照第 4 節的結果思考：CoT 錯在幻覺，ReAct 錯在檢索；兩者互相備援時最好。
  2. ReAct 和人類的思考方式有多像？還缺哪些認知機制？人有時靠經驗直接行動，有時先分析再做。可以延伸的方向包括：任務太複雜時先拆解、平行比較不同思路、納入過去的記憶與經驗、找出每個任務「推理」與「行動」的合適比例。講者特別提到，現在很多模型會過度思考，連簡單任務都產生很長的思考軌跡，怎麼讓模型不要想太多也是有趣的問題。另一個方向是組成 compound system：先評測各個模型，再依強項分派子任務。
  3. 環境回饋有雜訊、甚至是錯的時候怎麼辦？例如開放網路搜尋。agent 收到誤導性的回饋，可能會臨時編出內容。可以加一層輕量的反思，檢查環境給的資訊是否合理；推理鏈一直走不到結論時要能回溯，避免繞進迴圈；也可以把同一個任務跑很多次、取最好的一次，藉此估計模型對環境回饋的把握程度。

RLEF：用兩層測試建立回饋迴圈

▶ 00:28:07
一句話重點

公開測試在每一回合即時告訴模型哪裡錯，讓它在推論時自己修；私有測試全程隱藏，只用來決定 reward 並以 PPO 訓練模型。前者讓模型學會除錯，後者避免它把答案背起來。

寫程式是最適合建立 RL 回饋迴圈的領域之一，因為程式可以實際執行、拿到客觀的結果。RLEF 是早期清楚展示「有了執行回饋，code LLM 的表現能明顯提升」的論文。投影片指出，當 LLM 作為 coding agent 時需要兩項關鍵能力：準確推斷使用者的意圖，以及從中間結果取得有效回饋，才有辦法據此反覆修正。

整個框架是端到端的 RL 微調：動作是產生程式碼，觀察是執行測試的結果。點選下方各步驟，走一遍迴圈：

步驟依課堂投影片的流程圖整理。回文題的例子為講者口述的論文範例，本頁未取得完整程式碼。

公開測試 Public tests

  • 在迭代過程中使用
  • 提供執行回饋
  • 數量有限，讓迭代更快
  • 引導模型挑選與修正解法

私有測試 Private tests

  • 生成過程中完全隱藏
  • 決定解法是否正確
  • 涵蓋完整的測試集
  • 用於 PPO 訓練
為什麼要分兩層？投影片的說法是 避免資訊洩漏：如果拿來給 reward 的測試也是模型看得到的那一批，模型可能只是學會讓這些特定測試通過，而不是真的寫出正確程式。課堂上有學生質疑兩批測試都屬於訓練資料，這樣分的效果到底多大，講者表示並不完全清楚，留待課後討論。

RLEF 的 Reward 設計與 PPO

▶ 00:31:47
一句話重點

Reward 只看最後的結果：全部通過得 +1、有任何失敗得 −1、連有效程式碼都沒寫出來得 −0.2；policy 逐 token 產生程式碼，value function 卻以整個回合為單位評估。

RL 演算法本身就是 PPO，講者沒有細講，只強調兩個設計重點。先動手試試 reward 怎麼算：

動手試試：這一回合拿到多少 reward？

依投影片上的 reward 定義互動計算。

這一回合的輸出包含有效的程式碼嗎？
這是 episode 的最後一回合嗎？
私有測試全部通過嗎？
+1

投影片只列出 +1、−1、−0.2 三種情況。「中途回合且程式碼有效」時本頁顯示 0，這是依公式的結構推斷，不是投影片原文。

設計一：獎勵扣掉偏離原模型的程度

R(st, at) = r(st, at) − β · log[ π(at|ct) / ρ(at|ct) ]

後面那一項是相對於原始模型 ρ 的 KL divergence 懲罰：模型為了拿 reward 而偏離原本的輸出分布太多，就會被扣分。這是 RLHF 類方法常見的設計，避免模型為了追 reward 而喪失原有能力。

設計二：Token 層級的 policy，回合層級的 value

Policy（token 層級）

逐個 token 產生程式碼

對生成過程有最細的控制。

Value function（回合層級）

評估整段回應

用 prompt 的最後一個 token 計算 V(ct)，所以同一段回應裡的所有 token 共用同一個 advantage：At = R(st, at) − V(ct)。

講者把這種「reward 給整段序列、而不是逐 token 給」的做法，類比為近期的 GSPO 一類方法。在 CodeContests 上，每道題都附有測試，一部分當公開測試在推論時提供回饋，其餘拿來給 reward，就構成了讓模型變好的 RL 迴圈。

為什麼有效：錯誤分析

講者強調，base model 通常不會只因為看到錯誤解法和執行回饋就自動受益；真正有幫助的是在訓練時每一輪都讓模型面對執行回饋，而且這個能力能泛化到其他 benchmark。論文比較了三種模型在公開測試上的行為：原始的 Llama 3.1 Instruct、經 RLEF 訓練的模型，以及用隨機回饋訓練的 RLEF（訓練時給的錯誤訊息與實際程式無關）。

第 1 回合

錯誤類型改變

Constitutional AI：用 AI 回饋取代人類標註

▶ 00:45:51
一句話重點

RLHF 需要上萬筆人類偏好標註，很難擴展；Constitutional AI 改由人類只寫一份原則（憲法），之後的批判與偏好判斷都交給 AI，人類只需要待在「寫憲法」這一步。

回顧 RLHF：先讓模型產生回答，請人依正確性、有用程度、具體程度排序，再用這些偏好訓練 reward model，拿來微調模型。模型越大，RLHF 帶來的改善越明顯；問題是蒐集上萬筆人類標註非常耗時，不容易 scale。

轉機在於模型越來越會遵循指令：要求它用特定格式回答，它做得到；問它「這段回應有沒有某種行為」，它也能據實判斷。Constitutional AI（Anthropic 提出，Bai et al., 2022）就是利用這個特性。投影片的說法是：用大約 10 條人寫的原則，取代數以萬計的人類標註；論文實際使用的原則集合有 16 條。

RLAIF 階段與兩種取捨

▶ 00:51:43
一句話重點

RL 階段和 RLHF 幾乎一樣，只是把人類偏好換成 AI 依憲法給的偏好；結果是有幫助性只略低，無害性卻高出許多，加上 chain of thought 時取捨最好。

RL 階段分兩步：先用第一階段模型產生的回應與憲法訓練一個偏好模型，再微調 LLM 去最大化偏好模型的分數。投影片上的原則範例是：「選出以最周到、尊重且有禮的方式回答人類的那個回應。」偏好模型訓練時仍要保留驗證集，讓它對一批資料打分，再和人類的分數對照，確認兩者有一定的一致性。

訓練結束時，各方法落在哪裡？

橫軸是有幫助性 Elo，縱軸是無害性 Elo，越往右上越好。Elo 分數來自人類對成對回應的偏好比較。

延伸研究

RLAIF 與 Self-Refine

有後續工作直接比較 RLAIF 與 RLHF；Self-Refine 則用模型的自我回饋反覆修正輸出。也有研究用 RL 教模型 self-correction。

模型常常過度自信，不知道自己不知道什麼；用其他模型的共識來批判，有時效果更好。這仍是很活躍的研究方向。

課堂問答精選

學生在課堂上提出的問題，往往正好打在觀念最容易混淆的地方。先自己想一下答案，再展開對照。

模型怎麼知道自己什麼時候該搜尋、該搜什麼？它知道自己知道什麼嗎？

這有兩層。模型是否「知道自己知道」目前有正反兩種看法；但另一組研究顯示，直接問模型對自己輸出的信心，通常會發現它過度自信、校準不佳，這仍是待解的研究問題。因此從應用設計的角度，重點不是判斷模型是否知道自己知道，而是讓模型使用正確的工具，讓知識有所依據。若不同結果之間互相矛盾，可以用第 2 講的多數投票，或在交給使用者之前先驗證；終端應用需要更多 guardrail。

Thought 算不算 action space 的一部分？

形式上，ReAct 把語言空間併進了動作空間（Â = A ∪ L），所以 thought 是一種「不影響環境的動作」。講者在課堂上則傾向把兩者看成獨立的機制：推理在一個迴圈，動作在另一個迴圈。因為語言模型是用語言訓練的，把 reasoning token 放在合適的抽象層次，有助於模型輸出正確的動作，這是需要 thought 的主要原因。課末講者也補充：從 context 就是 state 的角度看，把 reasoning trace 視為一種 action 也說得通。

能不能比較 thought 與 observation 的 hidden state，看看兩者有沒有某種交錯的模式？

講者認為這可能還沒有答案。Observation 來自環境而不是模型自己產生，中間會不會出現某種變化值得研究；這可以當成這門課的專題，用開源 LLM 就能做。

Execution feedback 會指出錯在哪裡、甚至附上修正建議嗎？二元回饋夠用嗎？

講者的理解是比較像只告訴模型「這段出錯了」。這些競賽題的正確性問題通常不超過一行程式碼，算是小問題，所以簡單題用二元回饋可能就夠；更難的題目大概需要 error trace 或其他 metadata 才能有效除錯。講者認為這很適合做成專題。

Reward 只看最終結果，這樣會鼓勵模型第一次就寫對嗎？

目前的 reward 確實只是針對最終解的二元獎勵，不一定在鼓勵「一次就對」。講者的回答是，這取決於模型犯的是哪類錯誤：複雜問題本來就可能需要多輪；簡單問題則因為推論時的回饋會附上錯誤、公開測試先通過才進 PPO，模型某種程度上已經有幾次自我修正的機會。增加回合數或調整 reward 都可以試。整體結論是：至少在夠簡單的問題、搭配二元 reward 時，自我改進迴圈是有效的。

每一步都給回饋（process reward）比只看結果（outcome reward）更好嗎？

這個爭論還沒有定論。Process reward model 與 outcome reward model 哪個重要，在不同領域、不同 benchmark 可能要做不同選擇，每一步都給回饋不一定必要。至於直接在 reasoning trace 上做 SFT 是否也有效，講者表示有論文指出 SFT 仍能帶來一些提升；在領域內 SFT 一定有價值，但 RLEF 處理稍微新一點的問題時，泛化性似乎比 SFT 好一些。

偏好模型是用憲法訓練的，如果憲法改了，怎麼低成本更新、又確保舊規則被完全移除？

分兩層看。第一，RLHF 這類訓練屬於 post-training，放在模型訓練的最後階段，所需算力遠小於 pre-training；模型本來就會定期更新，憲法的修改可以跟著更新週期一起處理。第二，「讓模型忘掉舊規則、改遵守新規則」其實是 continual learning 的問題，目前仍是開放的研究題目；有些做法嘗試用 interpretability 讓模型忘掉特定知識，但還沒有被證明能可靠做到。

加上 chain of thought，是不是讓 helpfulness 變低了？

講者認為重點不在 CoT。如前一張投影片所示，無害性上升時，常常會和有幫助性呈現反向關係；特定情況下變得更無害確實可能犧牲一點有幫助性，但整體上還是能找到兩者的平衡。

拿模型自己批判、修訂後的輸出再去 fine-tune，模型不會失去原本的能力嗎？

這是很多地方都會用到的步驟，訓練模型「思考」時也類似：先產生一批 trace，讓模型依原則自我批評、修正，再拿這些 trace 去 fine-tune。講者指出，只要 fine-tune 的規模遠小於 base model 原本的訓練量，模型就不會失去原有能力，只是輸出分布會開始偏向這組回應。

這些改進 LLM 的技巧能轉到 agent 上嗎？能用 RL post-training 自動學出 workflow 嗎？

Agent 可以看成多個互相連接、有記憶與 session、能呼叫函式的 LLM，基礎仍然是「怎麼讓 LLM 用特定方式回應」。ReAct 的重要之處是定義了「先推理再行動」的工作流程，但每個任務的 workflow 高度依賴領域，很難有通用做法。RL post-training 能不能接手？有條件：搜尋空間能定義清楚就可以，例如動作空間與搜尋空間都有限的任務，可以讓模型去探索、使用工具、實際進入環境收集觀察；搜尋空間不清楚的任務則還做不到。

一頁總結

  1. 回饋來源決定方法：ReAct 用環境觀察、RLEF 用程式執行結果、Constitutional AI 用依原則產生的 AI 回饋；三者都在讓模型自我改進。
  2. ReAct 讓推理與行動交錯：Thought 不改變環境，只更新 context；觀察結果把推理拉回現實，減少幻覺，並產生可解釋的決策軌跡。
  3. ReAct 不是萬靈丹：知識任務上與 CoT 互相備援最好；WebShop 上勝過 IL 與 IL+RL，但成功率 40 仍遠低於人類專家的 59.6。
  4. RLEF 用兩層測試：公開測試在推論時提供錯誤訊息讓模型自我修正，私有測試隱藏起來決定 reward，再用 PPO 訓練。
  5. RLEF 學到的是除錯能力：訓練後的 Llama 3.1 以少得多的取樣預算達到頂尖水準；隨機回饋的對照實驗顯示，回饋內容本身才是關鍵。
  6. Constitutional AI 用原則取代標註：監督式階段以批判與修訂產生資料，RL 階段以 AI 偏好訓練偏好模型；人類只需要寫憲法。
  7. 取捨是核心：越無害可能越不有幫助；constitutional RL 加上 chain of thought 得到最好的取捨前緣，同樣的想法可推廣到任何規則集合。
