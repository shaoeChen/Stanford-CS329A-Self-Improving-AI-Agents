Planning 與多步推理：
從樹狀搜尋到平行思考

有些任務要走好幾步才能完成：先想、再查、再依結果修正。這一講用三篇論文說明 LLM 怎麼處理這類任務。LATS 在推論時把 Monte Carlo Tree Search 搬進 Agent，邊探索邊依回饋修正。SPRINT 用 fine-tuning 教 reasoning model 找出彼此獨立的步驟，再平行執行。SWiRL 則用離線合成的多步資料，加上逐步給分的 RL，讓模型學會一步步推理並呼叫工具。

01

多步任務：推理、行動、再修正計畫

▶ 00:00:37
一句話重點

多步任務不只要「想」，還要「做」：先推理出計畫，再採取行動蒐集資訊，然後依環境的回饋修正計畫。Planning 要解決的，就是怎麼在這條長軌跡上找到通往正確答案的路。

講者用「規劃一趟旅行」當例子。這種任務沒辦法一次想完就交出答案，它由三種步驟交錯組成：

先想清楚要做什麼

預算多少？行程怎麼排？這些就是規劃旅行時的思考過程。

難處在於：模型到現在仍然不太擅長產生多樣的解法、依照這些解法行動，或規劃好幾個步驟逐步逼近答案。只讓模型「產出一個計畫、然後照著做」是不夠的，我們希望它主動探索不同的計畫。而且步驟越多，前面的小錯誤越容易一路累積到最後。

本講的三個切入點：第一篇 LATS 從強化學習借來已知的搜尋技術，在推論時處理探索問題；第二篇 SPRINT 讓長推理裡的獨立步驟平行進行；第三篇 SWiRL 直接把多步推理與工具使用訓練進模型。
02

LATS：把樹狀搜尋帶進 Language Agent

▶ 00:02:58
一句話重點

LATS 把每個可能的動作當成樹的一個分支：實際在環境中執行、依結果打分，再用 MCTS 決定下一步往哪裡展開。推理（reasoning）、行動（acting）與規劃（planning）因此被整合在同一個框架裡。

Language Agent Tree Search Unifies Reasoning, Acting and Planning in Language Models
Andy Zhou、Kai Yan、Michal Shlapentokh-Rothman、Haohan Wang、Yu-Xiong Wang，ICML 2024

回到旅行的例子：要規劃夏威夷之旅，模型可以「問去過的朋友」，也可以「去看相關的 subreddit」。LATS 替每個動作打分，再依分數決定往哪裡展開。假設「問朋友」分數較高，就從這裡繼續，例如分別去問朋友 A 和朋友 B，再依回答的品質打分、往下搜尋。過程中會同時取樣好幾個動作（multi-action sampling），有些動作可以平行執行。

直覺上可以這樣理解：chain of thought 把推理拆成多步；LATS 則讓模型產生多個動作、展開成一棵樹，在樹上搜尋與規劃，再把從 ReAct 借來的「動作回饋」放進之後的搜尋。為了在「繼續挖目前最好的分支」和「試試別的分支」之間取得平衡，LATS 用的正是 MCTS（Monte Carlo Tree Search）。

04

UCT：在探索與利用之間取捨

▶ 00:13:09
一句話重點

UCT 分數＝目前的 value（exploitation），加上一個「越少被造訪就越大」的加分（exploration）。這讓搜尋不會只盯著眼前最高分的節點，而錯過暫時看起來差、其實更好的分支。

上一節的評估、選擇、反向傳播各自對應一條公式（取自投影片）：

Value function：LLM 當 judge 的分數（LM）與 self-consistency（SC）的加權平均V(s) = λ · LM(s) + (1 − λ) · SC(s)
選擇時使用的 UCT（Upper Confidence bounds applied to Trees）UCT(s) = V(s) + w · √( ln N(p) ÷ N(s) )
一條軌跡結束後，用回報 r 反向傳播更新路徑上的節點V(s) ← [ Vold(s) · (N(s) − 1) + r ] ÷ N(s)
N(s)
節點 s 被造訪的次數
N(p)
s 的父節點被造訪的次數
w
exploration weight，是一個超參數，控制要多重視探索
r
這條軌跡最後得到的回報，例如抵達出口為 1

UCT 的第二項是關鍵。如果一個節點相對於父節點很少被造訪，N(s) 小、加分就大，會鼓勵去試它；如果它已經被造訪很多次，加分變小，UCT 就可能低於還沒探索過的兄弟節點。反向傳播的公式則是「把新的回報併入平均」：舊的平均乘上舊次數、加上這次的 r，再除以新次數。這套做法借自 MCTS，背後有一些數學與理論直覺，但講者也提到它並沒有被證明是最佳解。

動手試試：調整 exploration weight w

這是示意模擬，不是論文的實驗。三個子節點的起始 value 取自上一節迷宮範例的評估分數，但每個分支「真正」的成功率是我們另外設定的：開右門（B）的評估分數最低，實際上卻最容易通往出口。每一輪用 UCT 選一個子節點、模擬一次（成功 r = 1，失敗 r = 0），再用反向傳播公式更新它。亂數使用固定種子，所以同一個 w 每次的結果都一樣。

已跑 0／40 輪

藍色長條＝造訪次數占比。外框加粗的卡片是下一輪會被選中的節點（UCT 最高）。

先把 w 設為 0 跑完 40 輪，再改成 0.5 或 1 比較看看。w = 0 等於完全不探索；w 很大時又會花太多輪在明顯較差的分支上。這正是 exploration 與 exploitation 的取捨。

05

LATS 的成果與限制

▶ 00:17:12
一句話重點

LATS 完全不做 fine-tuning，只靠推論時的搜尋，就在 HotPotQA 與 WebShop 上拿到很強的成績；代價是成本高，而且它假設動作做錯了可以「重來」。

HotPotQA 是多步推理的資料集：每一題至少要從兩個不同的 Wikipedia 頁面找資料，設計上就必須走多步才找得到答案。講者指出，增加取樣數或軌跡數時表現明顯提升，反思與把推理痕跡帶回搜尋也讓模型進步很多。換句話說，LATS 提供了一種機制，把推論時多花的算力轉成多步任務上更好的解法。

WebShop：在模擬商店裡買對東西

偏實際應用的環境：約 118 萬件真實商品、12,000 條人類撰寫的購物指令，Agent 要瀏覽網站並買到正確商品。例如要找一張「小型、可攜、已組裝好的桌子」，還得符合顏色、表面處理與價格條件。Score 是平均得分，SR 是成功率（success rate）。

優點

好移植、好實作

  • 把推理、行動與規劃串在一起
  • 把 MCTS 這類已知方法帶進語言模型
  • 在多個領域都有很強的結果
  • 只在推論時運作、模組化，容易套用到其他系統
限制

成本與「不能重來」的世界

  • 反覆展開與反向傳播很花錢，論文沒有真正分析成本效益
  • 假設動作可以撤銷。如果模型真的下單、付款，做了就回不去
  • 改進只存在單次推論中，不會留到下一次（投影片討論題 5）

課堂討論題

講者請同學花幾分鐘思考這篇論文的強項、弱點與可以延伸的方向。投影片上的五個問題：

  1. LATS 主要在偵測到失敗後才拆解任務。能不能延伸成事先預測失敗、主動拆解，而不是事後補救？
  2. 真實世界常需要同時執行多個任務，LATS 會怎麼處理？目前循序進行的做法有什麼侷限？
  3. 結構化的環境裡動作可以撤銷，但真實世界的決定常有永久後果。沒有「復原」選項時，LATS 該怎麼調整？
  4. LATS 整合了搜尋、推理與規劃，但許多決策還依賴其他認知功能。還能加入哪些「模組」？要怎麼整合？
  5. LATS 的改進只存在單一 session，無法延續到推論之外。要怎麼轉換成「學得起來」的範式？
和後兩篇的關係：第 2 題問的「同時執行」，正是下一篇 SPRINT 處理的問題；第 5 題問的「學得起來」，則是 SPRINT 與 SWiRL 用訓練來回答的方向。
06

SPRINT：讓推理模型平行規劃與執行

▶ 00:23:28
一句話重點

Reasoning model 想得越久越準，但冗長的思考裡藏著許多彼此獨立的步驟。SPRINT 教模型把獨立的計畫一起提出、平行執行，藉此減少必須依序產生的 token。

SPRINT: Enabling Interleaved Planning and Parallelized Execution in Reasoning Models
Emil Biju、Shayan Talaei、Zhemin Huang、Mohammadreza Pourreza、Azalia Mirhoseini、Amin Saberi，NeurIPS 2025

動機：想得久很有用，但也很慢

像 o1、Gemini 2.5 Pro 這類前沿 reasoning model，遇到難題時會想得更久，而更長的思考通常對應更高的準確率。講者引用 DeepSeek-R1 論文的兩張圖：隨著 RL 訓練進行，模型解數學題的表現變好，每次回應的平均長度也一路上升。

DeepSeek-R1-Zero 的 AIME 準確率（pass@1），訓練約 8,000 步約 16% → 約 71%
同一段訓練中，每次回應的平均長度數百 → 約 9,500 tokens

近似值，依課堂投影片上的 DeepSeek-R1 論文圖表判讀。

問題是，這些長推理裡有很多步驟其實彼此獨立：模型有時在嘗試不同解法，有時把任務拆成互不相干的子任務，有時在驗證前面的結果。這些計算不需要排隊依序產生。SPRINT 想讓模型自己辨識出可以平行的地方，並真的平行去做。這件事重要，是因為 LLM 推論的成本與延遲在多步推理時會變成很大的負擔：我們都不喜歡盯著畫面等模型慢慢吐字。

一句話重點

用 LLM 把現成的推理軌跡拆成「計畫＋執行」的步驟，畫出步驟之間的依賴關係（DAG），把互不依賴的步驟打包成同一階段，最後用這些重新排版的軌跡做 SFT。

想讓模型學會某種行為時，一個常見的手法是直接用 LLM 來協助建立 fine-tuning 資料。這個概念不只出現在 SPRINT，後面的 SWiRL 也會用到。依序點選五個階段：

流程取自投影片「SPRINT Fine-tuning Process」；步驟內容為示意。

推論時，微調過的模型會自己輸出這些標籤：先寫出計畫 i 的幾個子計畫，系統把它們平行執行、同步後把結果放回 context，模型再進入計畫 i+1。生成方式本質上仍是「預測下一個 token」，差別只在於用標籤標出「這是第幾個計畫、這是它的執行」，系統才能據此平行處理。

模型還能回頭修改計畫嗎？可以。SFT 只是讓模型偏好平行思考：能平行產生的計畫就直接一起產生，不必等計畫 1 執行完才寫計畫 2。模型仍然看得到全部的 context，想修訂先前的計畫時照樣可以做（見課堂問答）。
08

SPRINT 的實驗結果

▶ 00:36:08
一句話重點

SPRINT 在數學（訓練領域）上準確率更高、依序 token 更少，這種平行思考還能泛化到沒訓練過的 Countdown 與 GPQA-Diamond。思考越長的題目省得越多；很短的題目反而可能變慢。

講者說明的訓練配方：從數學資料集產生約 6,000 筆思考軌跡，保留平行程度較高的，再用重新排版的軌跡對 DeepSeek-R1-Distill-Qwen-7B 做 SFT。原本的目標是減少依序產生的 token，結果發現這種比較有結構的思考方式連準確率也一起提升，模型也更常探索、更常平行思考。

SWiRL：合成多步資料＋逐步強化學習

▶ 00:49:42
一句話重點

SWiRL 先離線產生多步的「推理＋工具呼叫」軌跡，請 LLM judge 替每一步打分，再對每一步做 RL。工具結果都已預先存好，所以 RL 訓練時完全不必真的呼叫工具。

從 SPRINT 接過來，講者指出：SFT 之外，RL（例如 GRPO）可能更能善用這類資料，對泛化通常也比較有幫助。SWiRL（Step-Wise Reinforcement Learning）延續「用模型產生多步合成資料」的思路，目標是讓模型把多步推理做得更好。

為什麼需要它

很多真實任務都需要多步推理與工具使用：用搜尋引擎回答 multi-hop 問題、解數學、做軟體工程專案、規劃旅行、分析資料。困難有三個：

困難一

錯誤會累積

單步推理和工具使用本身就不簡單，擴展成多步後，錯誤會一步步疊加。

困難二

訓練時呼叫工具很麻煩

工具可能失敗、很慢、有 bug，而訓練本身已經很耗時。

困難三

只看最終答案太粗

RLHF 這類流程多半只依最後答案給 reward，無法控制與優化中間每一步。

SWiRL 希望模型學會：

  • 判斷何時該呼叫工具
  • 寫出正確的工具查詢
  • 正確使用工具結果
  • 推理過程保持準確
  • 從錯誤中恢復
  • 知道何時停下來作答
  • 訓練時不必真的呼叫工具
  • 泛化到新工具與新任務

兩個階段

階段一：合成資料 離線、會呼叫工具

問題＋可用工具說明
→
推理／呼叫工具／作答
→
環境回應接回 context
→
LLM judge 替每一步打分
→
依分數過濾資料

透過自適應的 prompt，不同問題會產生一步、三步、甚至五步的軌跡。標註可以離線、大量平行處理。

階段二：逐步 RL 不呼叫工具

問題＋前面的步驟＋預存的工具結果
→
模型產生「下一個動作」
→
Judge 只評這個動作
→
更新模型

目標是：在給定前面所有步驟的條件下，最大化單一動作的預期 reward，並對第 1 到第 K 步都這樣做。

資料過濾的四種方式

Process filter

每一步都合理

只留 judge 認為每一步都好的軌跡，不管最終答案對不對。

Outcome filter

最終答案正確

只留答案正確的軌跡，不管中間的步驟標籤。

Process＋outcome

兩個條件都要

每一步合理、答案也正確，最嚴格。

不過濾

隨機取樣

當作對照組。

實驗設定（投影片）：合成資料由 Gemma-2-27B 產生，題目來自 HotPotQA 與 GSM8K；從 HotPotQA 收集 5 萬條軌跡，做成上述四種各 1 萬筆的子集；微調的基礎模型同樣是 Gemma-2-27B；process reward 由 Gemini 1.5 Pro 評分。

一個訓練樣本長什麼樣子

投影片的例子：「Glenn Hughes 和 Ross Lynch 誰比較年長？」依序點選三個步驟，留意 judge 每次看到什麼：

Judge 看不到工具輸出，怎麼打分？它評的是模型為了呼叫工具而寫出的查詢品質，不是工具的輸出。看到模型在查某人的年齡，即使還不知道答案，也能判斷「這是不是適合丟給搜尋引擎的問題」。這就是對每一步的 process reward。Judge 沒有另外訓練，只用 prompt 引導。

兩個重點。第一，多步 RL 明顯勝過 SFT。第二，SFT 的偏好剛好相反：對 SFT 來說，資料的正確性很重要，process＋outcome 過濾的資料比只做 process filter 好得多（CofCA 上只用 process filter 的 SFT 掉到約 14%）。這很合理：SFT 像是模仿學習，把軌跡示範給模型看、要它照著重現，示範裡有錯就學到錯；RL 則是在先前的步驟上給模型一次新的機會採取新動作，並依這個新動作給 reward，模型因此能跳脫原本的做法。

講者認為 SWiRL 最有趣的是泛化表現。用 GSM8K 數學題搭配計算機訓練，模型在 HotPotQA（搭配搜尋）上的表現也提升；反過來，用 HotPotQA 搭配搜尋訓練，在 GSM8K 搭配 Python 的表現也不錯。講者也提到，用 HotPotQA 訓練時，合成資料從 100 筆增加到 10,000 筆，模型面對完全不同的 GSM8K 數學題也會跟著變好，並稱這是論文裡最重要的一張圖：在容易產生合成資料的環境裡教模型使用工具、多步思考，這些行為能泛化到新的工具與領域。

課堂問答精選

學生在課堂上提出的問題，往往正好打在觀念最容易混淆的地方。先自己想一下答案，再展開對照。

在 bandit 問題裡，除了 confidence bound，還有其他挑選與探索的演算法。LATS 有比較過嗎？

沒有。Multi-armed bandit 的各種演算法，以及其他把 exploration–exploitation 放進最佳化流程的方法，其實都可以接到這個框架裡試。作者的主要貢獻比較像是建立一個平台，讓後續研究能把不同的最佳化方法接進來。

如果軌跡裡出現重複動作（例如 A、B、A、B），樹會把它們當成獨立的分支嗎？

概念上，同一個動作在給定父節點下重複出現時，會增加該動作的造訪次數，並反映在 UCT 公式中；理想上建樹時就會捕捉到這件事。這裡假設的結構是一棵樹，而不是全連接的圖。

SPRINT 的模型執行到第四個計畫時發現前面錯了，它怎麼知道該回頭修訂計畫 3 而不是計畫 2？

訓練教模型的是：每個時間點都去想計畫，即使只是修訂既有的計畫也一樣；能平行產生的計畫就直接產生，不要等計畫 1 執行完才寫計畫 2。模型仍然看得到全部的 context，想回頭修改哪個計畫都可以，它只是被訓練成更偏向平行思考。也正因為有特殊標籤標出計畫與執行，系統才能實際利用這些平行性。

平行分支各自看起來都對，合在一起卻互相矛盾，該以哪個為準？

不論是依序還是平行產生，結果最後都會放回 context，成為模型看到的思考過程，模型應該在給出最終答案前解決其中的矛盾。很難說哪一邊優先，因為兩種方式都可能出錯。另外，這裡的計畫比較像是「解同一題的不同步驟」，而不是「不同的解法」。

平行任務的長短不一時，會不會被最慢的那個拖住？

會，可能出現 straggler。例如 step 4 比 step 2 久很多，整體時間就由 step 4 決定，但仍然比「step 2 加 step 4」依序執行快。如果某個執行太簡單，會把它併進計畫裡，盡量做出較大、可平行處理的區塊。講者不確定論文是否有專門分析這一點。

這些 benchmark 的「樹寬」大概多少？能平行的空間有多大？

很看任務，講者沒有確切的數字。可以確定的是：方法要有用，任務本身必須存在平行性；目前觀察到數學、GPQA 等許多推理題都有。不同領域的程度不同，例如數學需要依序產生的 token 比例比 GPQA 低，代表平行性較高。

SWiRL 的 judge 有另外訓練嗎？它看不到工具輸出，分數可靠嗎？

Judge 沒有訓練，只用 prompt 引導（投影片註明以 Gemini 1.5 Pro 評 process reward）。它評的是模型寫出的工具查詢合不合理，而不是工具的輸出：看到「查 Glenn Hughes 的年齡」，不需要知道答案，也能判斷這是合理的一步。工具結果在資料標註階段就已經存進 context，不是在 RL 微調時才去取得。

一頁總結

  1. 多步任務：推理、行動、依回饋修正交錯進行；難處在於錯誤會累積，而且模型不擅長主動探索不同計畫。
  2. LATS：推論時用 MCTS 的六個步驟（選擇、擴展、評估、模擬、反向傳播、反思）搜尋動作樹；value 是 LM score 與 self-consistency 的加權平均。
  3. UCT：value 加上 exploration 加分；只看 value 可能永遠錯過暫時低分、其實更好的分支。
  4. LATS 的代價：不需訓練、容易移植，但成本高、假設動作可撤銷，改進也不會延續到下一次推論。
  5. SPRINT：用 LLM 把推理軌跡改寫成計畫／執行與 DAG，SFT 後模型會一起提出獨立計畫並平行執行；長推理題省最多，短題可能變慢，準確率也略有提升。
  6. SWiRL：離線合成多步資料、judge 逐步給 process reward、對每一步做 RL，訓練時不必呼叫工具。
  7. 資料過濾：對 RL，process filter 最好；對 SFT，答案正確更重要。多步推理與工具使用能跨領域、跨工具泛化。
