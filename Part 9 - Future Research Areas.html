01

一學期的回顧：從 LLM 到自我改進的 Agent

▶ 00:00:05
一句話重點

整門課的核心是一個迴圈：verifier 給回饋與 reward，再用 RL 或搜尋讓模型持續變好；這堂課要問的是，這個迴圈接下來會卡在哪裡。

講者先用幾分鐘把這一季的內容串起來。依上課順序大致是：

  1. Test-time scaling 與 train-time scaling以 verifier 的回饋與 reward 驅動自我改進，再用 RL 或搜尋演算法，在數學、程式等任務上一路往上爬（hill climb）。
  2. Evolutionary strategies 與 open-endedness不只靠 reward 推動，只要探索空間能被定義，就讓模型自己去探索。代表例子是 AlphaEvolve。
  3. Tool use 與端到端 workflow模型和環境、工具互動，把整個 workflow 從頭跑到尾。
  4. Retrieval 與 memory需要多步完成的任務，往往得查詢知識庫。
  5. Planning 與 multi-step reasoning、評估方法走向真實世界的 workflow，需要更好的規劃與多步推理，也需要新的評估方式來衡量下一代模型。
  6. 客座演講post-training、multimodal agent、機器人、推理等；Azalia 補充，其中一位講者談到 symbolic techniques，可歸在 tool use 之下，也能用來產生 synthetic data。

課名是 self-improving agents，重點在 agent 而不只是 LLM。回到第一堂的定義：Agent 是 LLM 的推廣，它有目標、會與環境互動、收集回饋，並用回饋修正自己的步驟。現階段 LLM 單靠自己還不足以一路完成整個目標，所以多半由人手寫 workflow 來編排 LLM、verifier（可能是 LLM as a judge）、tool call 與平行搜尋；但在 coding agent 等場景，已經看到 workflow 開始由模型自己驅動。

這堂課的結構

瓶頸一

多樣性

自我改進多半侷限在數學、程式等窄領域。推理鏈要夠多樣，迴圈才轉得下去，也才可能跨領域泛化。

瓶頸二

驗證

如何穩健地驗證推理過程，而不只看最後答案？這引出 meta-verification。

瓶頸三

資料

訓練用的 prompt 目前靠人工靜態挑選。如何打破這道資料牆，讓迴圈自己選資料？

第二部分則談 intelligence efficiency：自我改進需要大量推論，每單位資源能換到多少智慧，將成為下一個關鍵問題。講者也提醒，這個領域變化很快，這裡挑的是「指出方向」的論文，下次開課時可能每一篇都會變成一整堂課。

02

瓶頸一：推理鏈的多樣性

▶ 00:06:51
一句話重點

單一模型反覆「產生、過濾、微調」，答案會越來越像，幾輪後就停止進步；改用多個彼此辯論、各自微調的 agent，就能保住多樣性，讓自我改進持續下去。

問題：iterative finetuning 會停滯

擴大 pre-training 算力或做 instruction finetuning，都受限於真實人類資料的多寡：pre-training 本質上是壓縮網路規模的資料，instruction tuning 則需要人類偏好來判斷回答的好壞。替代方案是用 LLM 產生的 synthetic data 做 iterative finetuning：產生候選解 → 濾掉錯的（即 rejection sampling）→ 只拿好的解微調 → 重複。STaR、ReST 等變體都屬此類。

但投影片點出的共同問題是 plateauing：幾輪或幾十輪之後，表現不再上升，甚至下降。根源在於缺乏多樣性。Pre-training 資料由大量人類長時間寫成，天生多樣；單一模型對同一組 prompt 的輸出，即使把 temperature 調高也不夠多元。

做法：Multiagent Finetuning

直覺的解法是用多個各有專長的 agent。論文訓練兩種角色：generation agent 負責產生多樣的初始解，critic agent 負責評估與修正。逐步看一輪的流程：

和課堂熟悉的「單一 agent 加上 critique」相比，差別在於 critic 看的是多個 agent 回答的摘要，而不是單一回答。多樣性在生成階段就已經存在，等於「免費」得到一種 majority voting。講者也提到窮人版做法：直接拿不同的模型、不同的 prompt 來產生多樣的回答，實務上也有人這樣做。

03

瓶頸二：驗證與 Meta-verification

▶ 00:15:31
一句話重點

答案對不代表推理對。DeepSeekMath-V2 訓練一個會挑證明毛病的 verifier，再加一個檢查「verifier 挑的毛病是否真的存在」的 meta-verifier，讓定理證明的自我驗證迴圈得以自動化。

目前的 RL 做法多半只看最後結果：用 outcome reward model 比對最終答案與標準答案，相符就給 reward。這套方法讓 AIME 等數學 benchmark 趨近飽和，但有兩個問題：

問題一

答案對，推理不一定對

定理證明需要嚴謹的逐步推導，光看最後輸出看不出來。若推理鏈是錯的，模型可能被帶偏。而評估每一步的 process reward model 又很難建。

問題二

LLM as a judge 在這裡不太行

LLM 產生的證明常常在數學上無效，請它自己檢查，它還會宣稱錯的證明是對的。反觀專家能指出「這一步並沒有從上一步推出」這類推理缺口。

DeepSeekMath-V2 的三個角色

做法是先請人類在沒有參考解的情況下標出證明中的問題，用這些資料訓練 LLM 去辨識證明的問題並評分。架構上仍是熟悉的 generator–verifier 迴圈，多了一層 meta-verifier：

Generator
產生證明，具備自我驗證能力
→
Verifier
找出問題並評分：0、0.5、1
→
Meta-verifier
檢查 verifier 的分析是否忠實

↺ Verifier 改進 generator；generator 產生更難的證明，又回頭改進 verifier。驗證規模化之後，標註也能自動化。

為什麼需要 meta-verifier？因為 verifier 本身也會出錯，例如捏造出不存在的錯誤，或給出與自己指出的問題不相符的分數。Meta-verification 檢查兩件事：verifier 指出的問題真的存在嗎？分數真的由這些問題推得嗎？論文請專家標註這類評估的品質，光是加上這一層，驗證品質就提升了。一旦有了 seed 資料、meta-verifier 也學會之後，就不必一直依賴人類找錯。

04

瓶頸三：讓模型自己出題

▶ 00:23:07
一句話重點

Absolute Zero 讓同一個模型兼任出題者與解題者，用程式執行器驗證，並用「難度剛好」的 reward 引導出題；完全不用人工整理的題目，就在程式與數學 benchmark 上達到頂尖水準。

現在的訓練流程中，SFT 階段需要人工整理的 reasoning trace，RLVR 也需要專家整理問答配對：做數學要數學專家，做 IMO 要 IMO 等級的專家，做程式要強的工程師。模型越強，找得到的專家與題目就越少，資料本身變成瓶頸。講者說這篇論文當時還沒什麼人討論，但想法很有意思：走到另一個極端，完全不需要外部的人類 prompt。

兩個角色共用同一組權重，一起更新，而不是只更新其中一邊。

三種任務：遮住 program、input、output 中的哪一個

任務以 Python 程式為基礎。一個任務就是一組三元組（program, input, output），差別在於解題者要推出哪一個。切換看看：

範例程式為示意，不是論文中的實際任務。任務類型的定義取自投影片的流程圖。

出題時，出題者會參考 buffer 裡 K 個過去自己產生的範例，並被明確要求「出不一樣的題目」，以促進多樣性。題目產生後還要先驗證才能進入訓練：程式能否正常執行、是否通過安全檢查、同一個 input 執行多次是否得到相同 output。這一步防止出題者鑽漏洞、丟出垃圾任務。

出題者的 reward：難度剛好最好

投影片上的公式：解題者平均成功率為 0 時 reward = 0，否則 reward = 1 − 平均成功率。成功率以解題者在非零 temperature 下多次作答（Monte Carlo rollouts）估計。下方假設每題試 8 次，次數為示意。

直覺是：太簡單（全對）和不可能（全錯）的題目都提供不了學習訊號，有時對、有時錯的中等難度題目最有價值。模型變強之後，出題者也必須學會出更難的題目。每個驗證過的三元組都放進 task buffer（論文從單一個 identity function 開始），並記錄模型在每題上的成敗次數，於是形成一份隨時間演進的 curriculum。

結果與觀察

結果

零人工資料也能頂尖

只在自己出的程式題上訓練，就在程式與數學 benchmark 上達到 state-of-the-art，勝過用數萬個人類範例訓練的模型。

意外的遷移

數學也跟著變好

沒有訓練任何數學題，數學 benchmark 卻也有強表現。講者認為這可以從領域中其他結果來理解（見第 05 章的 SWiRL）。

湧現的 curriculum

難度與多樣性自然上升

複雜度指標隨訓練上升，程式與答案的多樣性也變好。出題者與解題者有點對抗，但整體在互相幫助進步，有點像賽局。

規模效應

大模型受益更多

投影片的數字：14B 模型提升 13 分以上，3B 模型提升 6 分。

關鍵前提：出題迴圈之所以不必依賴人類，是因為程式有現成的驗證機制（執行器）；它也需要做 curriculum learning 的能力。只要任務選擇卡在人類資料上，迴圈就會受限於「找得到哪些專家」。
05

可驗證與不可驗證的領域

▶ 00:31:52
一句話重點

Synthetic data 帶來的進步會遷移到其他能力，而且大模型更吸收得了；一個值得研究的方向是：只在可驗證的領域自我改進，能不能讓模型在不可驗證的領域也變聰明？

反覆出現的趨勢：synthetic data 會遷移

Azalia 補充，這和課堂上講過的 SWiRL（step-wise RL with synthetic data）的發現互相呼應：SWiRL 用 retrieval 做 multi-hop question answering 的 synthetic data 做 RL 訓練，結果模型在其他 tool calling 任務（例如呼叫 Python 解數學題）上也變好，反過來也成立。兩篇論文的共同觀察：

  • 模型產生自己的訓練資料，進步不只在該任務上，還會遷移到其他能力。
  • 越大的模型越能吸收這種 data flywheel 並泛化，至少在 RL 最佳化這一側是如此。

什麼是「不可驗證」的領域？

驗證太慢 回饋要等好幾天

科學發現；晶片設計中要跑好幾天的模擬；化學實驗得進 wet lab 才知道結果。RL 微調需要成百上千步的迭代，verifier 必須幾乎即時，頂多等幾分鐘或一小時，不可能每一步都等好幾天或等人類回饋。

本質上主觀 難以定義 reward

創意寫作這類帶主觀成分的指標，很難設計精確的 reward function。當然可以用模型去近似，但只要近似得稍有偏差，RL 或 agent 就可能 reward hacking。

難以驗證時的兩種做法

做法一

訓練替代的 reward model

先離線收集大量模擬或實驗的資料，訓練一個 reward model 去預測「給定輸入，輸出品質如何」，再用它當 RL 迴圈中的 verifier。缺點是它的泛化能力取決於資料量，可能不準，進而造成問題。

做法二

把問題拆小

Aakanksha 以 Stanford 的 KernelBench 為例：寫 kernel 時，編譯與執行能告訴你程式對不對；但要讀懂 performance profile、協調多個部分一起最佳化就難得多。常見做法是把問題拆成模型能處理的子問題，搭配參考解與知識庫。

Azalia 提出的研究方向：在可驗證的多樣任務上盡量推進自我改進，看看能不能泛化到沒有自動驗證的領域，讓模型在可驗證領域越來越聰明，同時減少、甚至消除不可驗證領域對標註資料的需求。這當然是非常吃算力的實驗。

06

智慧的成本：大型主機時代

▶ 00:40:03
一句話重點

Intelligence per Watt：衡量智慧的效率

▶ 00:46:25
一句話重點

Intelligence per watt（IPW）＝平均任務準確率 ÷ 平均功耗。兩年內本地推論的 IPW 提升了 5.3 倍，其中模型進步貢獻 3.1 倍、硬體進步貢獻 1.7 倍。

為了有系統地研究這件事，團隊定義了一個同時看能力與效率的新指標：

Intelligence per watt ＝ 平均任務準確率 ÷ 平均功耗

單位為 accuracy / W，衡量推論系統把能源轉換成「有用運算」的效率

能力面

本地模型答得對多少？

現今單輪聊天與推理類查詢中，本地模型能正確回答的比例。這裡的「本地模型」指 active parameters 不超過 20B 的模型。

效率面

每瓦換到多少有用運算？

在本地硬體上跑本地模型時，每一瓦能換到多少「正確的推論」。

研究設計

模型20 多個頂尖本地模型，例如 Qwen3、gpt-oss、Gemma3、IBM Granite（1B 到 200B 參數）
硬體3 款本地加速器（2023 到 2025 年，如 Apple M4 Max）與 5 款企業級加速器（NVIDIA、AMD、SambaNova），後者用來建立 IPW 的上限
工作負載100 萬筆查詢，來自真實 ChatGPT 對話（WildChat）、一般推理（Natural Reasoning）與標準 benchmark（MMLU-Pro、SuperGPQA）
評估單一查詢推論（batch size = 1）下的準確率、能耗、延遲、算力等。資料將開源

發現：本地 AI 可行，而且進步很快

數值取自投影片圖上的標示。IPW 原始數值為 7.92e-4、1.80e-3、4.18e-3。

以表格檢視
  • 本地模型已經很強：投影片寫道，本地模型能正確處理 88.7% 的查詢；2023 到 2025 年準確率提升 3.1 倍（23.2% → 71.3%）。
  • 本地加速器仍落後企業級晶片：Apple M4 Max 的 IPW 比 B200 低 1.5 倍。B200 是為 LLM 工作負載高度最佳化的晶片，本地晶片還要兼顧其他工作；過去設計晶片時，也沒預期 LLM 會在本地執行。
  • 效率兩年提升 5.3 倍：3.1 倍來自更好的模型，1.7 倍來自更有效率的硬體（兩者相乘約 5.3）。

兩股趨勢加在一起，代表未來會有越來越多流量可以交給筆電、手機這類邊緣裝置處理。

自我改進這一側

  1. Test-time scaling 與 synthetic data flywheel 的基本原理為什麼同一個問題反覆問模型，正確答案就會冒出來？這說明了模型的什麼性質？把成功的軌跡蒸餾回模型的最佳做法是什麼？這些都還是開放問題。
  2. 從即時產生的 test-time 經驗做 continual learning人類解題、學習時能力是持續成長的；模型則多半是離線收集經驗、隔一段時間再微調，不是邊做邊學。如何把成功與失敗的經驗更自然地帶回模型，而不是目前「非同步產生資料再微調」的模式？
  3. 高吞吐、低延遲的 test-time scaling 基礎設施Repeated sampling、對先前生成來回修改、tool calling……這些用法和主流的單輪聊天很不一樣，系統與推論最佳化大有可為。Azalia 的實驗室做過 Hydragen、Tokasaurus 等相關工作。

方向一

混合式推論服務

新的 inference serving engine，依需求與複雜度，在本地與雲端的模型和加速器之間順暢地分流。

針對本地加速器做加速器與架構的 co-design。相較於雲端加速器，這塊受到的關注少很多。

能源將是最珍貴的資源。跨任務、硬體與部署情境量測並最佳化 IPW，目前還很少有人把它當作最佳化目標。

Continual Learning 的幾條路

▶ 00:59:17
一句話重點

Continual learning 不一定要改權重：也可以靠外部記憶、超長上下文，或把資訊放進 KV cache；但若要學會新技能、推理新領域，更新權重往往是必要的。

課堂最後的問答圍繞在「模型要怎麼持續學習」。整理兩位講者提到的幾條路：

途徑做法適合限制
更新權重微調全部或部分權重，把成功與失敗的經驗寫進模型學新技能、推理新領域、技能遷移（例如機器人的跨身體泛化）目前多為離線、非同步；「學會如何學習」的能力仍欠缺
外部記憶庫維護一個 LLM 會去查的資料庫，有新知識就更新資料庫知識型內容，更新最簡單側掛的記憶系統通常教不會模型推理新領域
超長上下文把所有正面與負面經驗都放進 context，靠 in-context learning理論上不需要改權重沒有無限長的 context；即使到百萬 token，推理能力也會下降
放進 KV cache如課堂介紹過的 Cartridges：把資訊帶進 activations／KV cache，而不微調模型有效擴大上下文、實現某種長期記憶講者僅提出作為一種思路

Aakanksha 的看法是：長期記憶系統是人類的類比，但在那之前，連「在多步推理中從成功與失敗學習、保留技能、以有用的方式更新部分權重」都還做不到。她舉的願景是：能不能看影片就學會做一件事，而不是需要大量示範？機器人研究正在嘗試這件事。

課堂問答精選

學生的提問往往正好打在最容易混淆的地方。先自己想一下答案，再展開對照。

有哪些應用不屬於可驗證的問題？

Azalia 舉了兩類。第一類是驗證很慢：科學發現、晶片設計中要跑好幾天的模擬、得進 wet lab 才知道結果的化學實驗。RL 需要成百上千步的迭代，每一步都等好幾天或等人類回饋是不可行的。第二類是本質上主觀，例如創意寫作，很難設計精確的 reward function；用模型近似的話，只要稍有偏差就可能被 reward hacking。

晶片設計這類難驗證的領域，現在大家怎麼做？

一種做法是另外訓練一個 reward model 來預測模擬的結果：先離線收集大量資料，訓練它根據輸入預測輸出品質，再用它取代昂貴的模擬或實驗，放進 RL 迴圈當 verifier。但它的泛化能力取決於資料量，可能不準。Aakanksha 補充 KernelBench 的例子：簡單的 kernel 能靠編譯與執行驗證，但要讀 performance profile、改進多個部分就難得多，實務上常把問題拆成子問題，再搭配參考解與知識庫。

從成功與失敗中持續學習，會更偏向長期記憶系統，還是改進模型本身？

Aakanksha 認為長期記憶是人類的類比，但更基本的能力都還缺：在多步推理中從成敗學習、保留技能、有效更新部分權重，甚至學會如何學習。Azalia 補充，in-context learning 也是一條路：如果有一個無限長、模型能完整利用的 context，把所有經驗放進去就能持續學習；但現實中 context 一長，推理能力就下降。另一種是 Cartridges 這類方法，把資訊帶進 KV cache 而不微調模型。

實作上，不斷更新模型權重比較容易，還是更新記憶庫比較容易？

看應用。如果是知識庫，更新資料庫最簡單。但如果要教模型推理新領域，側掛的記憶系統通常做不到，更新權重效果更好。機器人是很好的例子：跨身體的泛化屬於技能遷移，再多記憶系統也無法取代更新模型權重。

Absolute Zero 的環境像是用來 post-training 的資料，有沒有讓 agent 自己建立環境的論文？

Aakanksha 回答，在過去的窄域智慧時代，可以為遊戲寫模擬器當作玩具任務的環境。現在環境之所以重要，是因為它們是真實世界任務的代理。重點不在於「agent 能不能自己建立環境」，而在於你想代表哪些任務、能不能輕易模擬，以及模擬是否合理反映模型與真實世界互動時得到的回饋。遊戲的探索空間有限，比較容易用程式模擬。

11

一頁總結

  1. 自我改進迴圈的三個瓶頸：推理鏈的多樣性、驗證的可靠度、訓練資料的來源。
  2. 多樣性：單一模型反覆自我訓練會停滯；多個 agent 互相辯論、各自微調，能保住多樣性並泛化到相鄰資料集。
  3. 驗證：答案對不代表推理對。DeepSeekMath-V2 用 verifier 挑證明的毛病，再用 meta-verifier 檢查這些毛病是否真的存在。
  4. 資料：Absolute Zero 讓模型自己出題、自己解，以程式執行驗證，以「難度剛好」的 learnability reward 引導出題，零人工資料達到頂尖表現。
  5. 遷移與不可驗證領域：Synthetic data 的進步會遷移、大模型更吸收得了；如何讓可驗證領域的進步帶動不可驗證領域，是開放問題。
  6. 智慧的效率：IPW＝準確率 ÷ 功耗。本地推論的 IPW 兩年提升 5.3 倍，未來更多流量可交給邊緣裝置，混合式推論服務因此值得研究。
  7. Continual learning：外部記憶與長上下文能補充知識，但要學會新技能，往往仍需更新權重。
