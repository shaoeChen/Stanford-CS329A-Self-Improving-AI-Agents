01

為什麼需要驗證

▶ 00:00:05
一句話重點

模型「產生得出」正確答案，不代表我們「挑得出」正確答案；verifier 就是用來縮小這個落差的工具。

上一講談 test-time scaling：對同一題重複取樣，coverage（至少一個樣本答對的比例）會隨取樣數持續上升。但 coverage 只是理論上限，前提是有人能從幾十、幾百個候選中把正確的那個挑出來。產生答案與判斷答案之間的差距，就是 generation-verification gap。

上一講也看過最簡單的挑法：majority voting（多數投票，又稱 self-consistency），也就是選最常出現的最終答案。它不需要任何額外模型，但取樣數變多之後很快就停滯。這一講要問的是：能不能訓練或組合出更好的「評審」？

這一講的四篇論文

  1. Training Verifiers to Solve Math Word Problems2021Cobbe 等人，OpenAI。提出 GSM8K，並訓練一個替整個解答打分的 verifier。
  2. Let's Verify Step by Step2023OpenAI。比較只看結果的 ORM 與逐步打分的 PRM，釋出人工標註的 PRM800K。
  3. Math-Shepherd: Verify and Reinforce LLMs Step-by-step without Human Annotations2023Wang 等人。用模型自己的 rollout 自動產生步驟標籤，並把 PRM 用在 RL 訓練。
  4. Shrinking the Generation-Verification Gap with Weak Verifiers2025Saad-Falcon 等人，Stanford，講者稱為 NeurIPS 2025 論文。提出 Weaver：不訓練新的 verifier，而是加權組合現成的多個 verifier。

第二篇的英文標題由整理者補上（字幕只說「OpenAI 的逐步驗證論文」）。第四篇的投影片寫成 2023，但講者口述它是幾個月前發表的 NeurIPS 2025 論文，這裡採用 2025。

02

第一代 Verifier：GSM8K

▶ 00:02:21
一句話重點

讓 generator 每題產生 100 個解答，用標準答案自動標出對錯，再訓練一個 verifier 預測「這個解答正確的機率」；測試時取 verifier 分數最高的解答。

2021 年的 LLM 很容易產生幻覺，而且會很有自信地給出錯誤答案。這篇論文有兩個貢獻：

貢獻一

GSM8K 資料集

約 8,500 題小學數學應用題，強調品質、多樣性與多步推理：每題本身不難，但要經過幾個步驟才算得出來，解法用自然語言寫成。講者提到，它到今天仍適合拿來評估小型模型，同學做專題時也可以考慮。

貢獻二

訓練一個 verifier

輸出「某個解答正確的機率」。就像人解題時如果有一套評分標準能判斷自己對不對，會很有幫助；verifier 想提供模型同樣的東西。

訓練與使用流程

補充：第一步先 fine-tune generator，在今天是否還必要有討論空間。現在的模型已經很會遵循指令、也懂數學，很多較新的 verifier 會直接訓練 verifier 目標，不先做監督式微調。

Token 層級的預測長什麼樣子？

論文的消融實驗比較了兩種標註粒度：只在整個解答層級預測，或對每個 token 都預測「從這裡走下去會不會答對」。講者提到 token 層級的標籤雜訊較大；依原論文的結果，token 層級的 verifier 表現仍較好（此點為整理者依論文補充）。測試時只看最後一個 token 的預測，當作整個解答的分數。

verifier 認為會答錯verifier 認為會答對

依課堂投影片的例題翻譯重繪。原圖對每個 token 上色，這裡簡化為每一句一個顏色，分數為依顏色判讀的近似值。

例一開頭幾句偏紅：模型把「每天早上一份 3 顆蛋的蛋捲」讀成「每天 3 份蛋捲」，雖然數字湊巧沒錯，verifier 一開始並不確定；越接近結尾越綠，最後判斷正確。例二前面還不錯，最後一步只扣掉星期三的花費，漏掉星期一與星期二（正解是 100 − 8 − 16 − 64 = 12），verifier 在這裡轉紅，最後判斷錯誤，與實際結果一致。

Verifier 什麼時候有用？

▶ 00:10:56
一句話重點

資料夠多時 verifier 明顯勝過單純 fine-tuning；但候選答案不是越多越好，超過某個數量後，騙過 verifier 的錯誤答案會越來越常被選中。

兩種規模的模型都呈現同樣的模式：訓練資料少時，verification 反而不如 fine-tuning，投影片的解釋是 verifier 過擬合；資料量夠大後，verification 大幅領先。175B 模型在 8,000 題時，verification 約 56%，fine-tuning 約 34%。

講者也提到 fine-tuning 與 verification 的一個差別：verifier 不需要去改動基礎語言模型，generator 可以保持通用，不會被過度特化到單一資料集。

Generator 大一點，還是 verifier 大一點？

論文比較了「大 generator ＋小 verifier」與「小 generator ＋大 verifier」，結果是放大 generator 的影響比放大 verifier 大。如果平均來說產生答案比驗證答案難，這個結果就很直覺。講者認為兩者的尺寸如何取捨（找出 Pareto 最佳點）是很好的研究題目，尤其現在 generator 進步很多，Hugging Face 上也有 reward model 的排行榜可以拿來實驗。

候選答案越多越好嗎？動手試試

原論文的實驗：每題的候選數從 25 增加到 3,200，解題率在約 400 個時達到最高（約 39.6%），之後一路下降到約 37%。實務上他們做到每題 100 個就停了，因為大部分的收益已經拿到。

為什麼會下降？這裡顯示的是整個系統挑出來的答案，而不是 coverage。候選越多，越可能出現一個「說服力很強、但其實是錯的」答案拿到最高分。下面的模擬器用這個機制重現了「先升後降」的形狀。

每題候選數 N1
coverage（至少一個候選正確）0%
verifier 挑中正確答案的比例0%
verifier 挑中正確答案coverage（理論上限）

示意模擬，不是論文數據：400 道虛構題目，每題的難度不同；verifier 對正確答案平均給較高分，但有一小部分錯誤答案會拿到異常高分。使用固定亂數種子，每次開啟結果相同。

04

ORM 與 PRM：看結果，還是看過程

▶ 00:21:29
一句話重點

ORM 只替整個解答打一個分數；PRM 替每一步打分，再把各步「正確」的機率相乘。PRM 比較抓得到「過程錯、答案碰巧對」的解答。

第二篇論文的出發點：LLM 會產生幻覺、犯邏輯錯誤，而只要一個步驟出錯，整個解答就可能被帶偏。它比較兩種 reward model：

Outcome Reward Model

ORM：替整個解答打分

訓練資料是「解答＋最終答案對或錯」，有標準答案就能自動產生。分數取完成序列最後一個 token 的預測，和第一篇論文的做法相同。

Process Reward Model

PRM：替每一步打分

需要人工逐步檢查模型的解題步驟，標出每一步是否正確。最終分數是各步「正確」機率的乘積。這種做法稱為 process supervision。

同一份解答，兩種評法

題目：一個分數的分母比分子的 3 倍少 7，這個分數等於 2/5，分子是多少？（正解：14）

    解答甲改寫自課堂投影片上的 PRM800K 標註範例；解答乙是整理者為了說明 false positive 而補充的例子。各步的機率為示意數值。

    Process supervision 的三個好處

    好處一

    更精細的 credit assignment

    不只知道整份解答錯了，還知道錯在哪一步。

    好處二

    較能處理 false positive

    模型可能推理很錯、最後答案卻正確。只看結果抓不到，逐步檢查就比較不會落入這個陷阱。講者認為這是 test-time scaling 的潛在陷阱之一。

    好處三

    鼓勵可解釋的推理

    標籤由人類建立，等於在獎勵人類認可（human-endorsed）的解題過程。

    PRM800K 與實驗結果

    ▶ 00:26:05
    一句話重點

    OpenAI 花大量人力建立 80 萬筆步驟層級標籤；用它訓練的 PRM 勝過 ORM 與多數投票，而且在沒見過的考科上仍然領先。

    PRM800K 是開源的資料集，包含約 80 萬筆步驟層級標籤，每一步被標為正向、負向或中性。建立方式：

    1. 大量產生逐步解答用語言模型對每題以逐步的格式產生許多解答。
    2. 優先挑「有說服力的錯誤解答」給人標比隨機挑樣本給人標，資料效率高了 2.6 倍。
    3. 反覆迭代用收集到的標籤訓練 PRM，再用更好的 PRM 挑下一批要標的樣本，逐步提升資料品質。
    名詞校正：講者把「有說服力的錯誤解答」描述為「最後答案正確、但中間步驟錯誤」的樣本。依原論文（Lightman 等人，2023）的定義，convincing wrong-answer solution 指的是目前的 PRM 給了高分、但最終答案錯誤的解答。兩者都是在找 PRM 容易看走眼的樣本，但定義不同，引用時請以論文為準。

    實驗設定：generator 是 GPT-4 base model，ORM 與 PRM 都從 GPT-4 fine-tune 而來。ORM 的資料是「生成樣本＋最終答案對錯」，PRM 的資料是「生成樣本＋PRM800K 的逐步標籤」。

    在沒見過的考科上（OOD 泛化）

    以 MATH 訓練的模型，直接拿去解 AP 考題與 AMC 競賽題，最佳者以粗體標示。

    資料來源：課堂投影片（Lightman 等人，2023）。

    講者的整理：PRM 在 best-of-N 的設定下明顯勝過 ORM 與多數投票，也能挑出那些在樣本中佔比很低的正確解；主動學習（優先標註難樣本）讓資料更有效率；而且 PRM 能承受中等程度的分布偏移。值得注意的是，在 OOD 考科上，多數投票有幾科反而比 ORM 好，但 PRM 整體又比多數投票更好。

    代價：PRM 的標註成本高得多。ORM 每份解答只要一個標籤；PRM 則要乘上步數，而步數很難精確控制，所以兩者的標註成本不容易公平比較。PRM 的門檻值也是一個額外的超參數。講者提到，很多新方法會把 PRM 與 ORM 結合，想同時拿到兩邊的好處。
    06

    Math-Shepherd：不用人工的步驟標註

    ▶ 00:37:51
    一句話重點

    一個步驟的品質，定義為「從這一步出發，最後能走到正確答案的潛力」；從該步往後 rollout N 次，看有幾次答對，就能自動產生標籤。

    PRM 比 ORM 有潛力，但人工逐步標註太貴。Math-Shepherd 的問題是：PRM 的標籤能不能自動產生？做法是對某個中間步驟，讓模型接著往下完成 N 次，再用最終答案的對錯回推這一步的分數：

    Hard Estimate（HE）

    有沒有任何一次答對

    N 次 rollout 中只要有一次得到正確答案，這一步就標為 1，否則為 0。

    Soft Estimate（SE）

    答對的比例

    N 次 rollout 中答對的次數除以 N，得到 0 到 1 之間的分數。

    題目：p(x) 是首項係數為 1 的四次多項式，其中三個根是 1、2、3，求 p(0) + p(4)。（正解：24）

    rollout 次數 N 3
    Hard Estimate1
    Soft Estimate2/3

    題目取自課堂投影片；投影片中第一步、N = 3 時得到 SE = 2/3、HE = 1。其餘步驟與各次 rollout 的結果為示意模擬，使用固定亂數種子。

    這個方法的弱點

    • 好步驟可能被低估。如果一條路徑很少見、或解法很不尋常，可能要 rollout 上百次才看得到那條通往正解的軌跡；只取 3 次就會被標成 0。題目很難時，大部分 rollout 本來就答錯，訊號很弱。
    • 錯步驟可能被高估。中間步驟錯了，後續卻碰巧得到正確答案時，這一步仍會被標為正確。樣本夠多時也許能看出問題，但沒有保證。
    • 前提是題目有標準答案。沒有可比對的最終答案，就無法回推步驟分數。

    Hard 與 Soft 標註的比較

    N 越大，soft 標註的 loss 持續下降，hard 標註在 N = 4 之後反而回升。講者的說明是：在 N = 4 時兩者差不多，而論文最後採用 hard estimate，因為比較容易計算。

    結果

    在 best-of-N 的設定下，Math-Shepherd 的 PRM 勝過 self-consistency（多數投票）與 ORM。整個流程沒有任何人工標註，卻在 MATH 上勝過用人工標註 PRM800K 訓練的 PRM。依投影片圖表判讀，N = 256 時 MATH 的解題率約為：Math-Shepherd 44.5%、PRM800K 41%、ORM 40%、self-consistency 39.5%；在比較簡單的 GSM8K 上差距較小。

    08

    Weaver：把弱驗證器組合成強驗證器

    ▶ 00:51:49
    一句話重點

    不訓練新的 verifier，而是把現成的多個 reward model 與 LLM judge 組合起來；關鍵在於替每個 verifier 估計可信度並加權，而不是單純平均。

    投影片上的動機：已經有很多驗證方法被提出，但沒有一個能消除 generation-verification gap。能不能改用推論算力，具體來說是集成多個 weak verifier，來縮小這個差距？

    這裡的 weak 是指「沒有任何一個 verifier 是完美的」，並不是刻意挑差的。它們是現有最好的 verifier，和真實標籤有相關，但都有缺陷。可用的 verifier 不只 PRM 與 ORM：

    類型一

    Reward model

    Weaver 的步驟

    弱監督背後的假設

    Weaver 借用 weak supervision（受 Snorkel，Ratner 等人 2017 啟發）：一系列把多個雜訊很大的標註來源，透過建模它們的準確度與相關性，推論出真實標籤的統計方法。設定是 n 個題目、每題 k 個解答、m 個 verifier，目標是估計

    Pr( 解答 yij 正確 | 第 1 到第 m 個 verifier 的分數 )

    關鍵假設是：每個 verifier 捕捉的是正確性的不同面向，在給定真實答案時彼此獨立。如果所有 verifier 對每個樣本的判斷都一模一樣，我們就學不到新東西；有用的訊號正是來自 verifier 之間哪裡一致、哪裡不一致。在這個假設下，任兩個 verifier 的共同判斷分布可以拆成「各自的準確度」的乘積，因此只看 verifier 彼此的一致程度，就能反推每個 verifier 有多準，不需要大量標籤。

    課堂最後的延伸討論

    • 數學之外：程式也是很適合研究推理與驗證的領域。之後會談到 CodeMonkeys：它不直接訓練 verifier，而是讓模型在測試時自己產生 unit test，再用這些測試當 verifier。
    • Reasoning model 還需要 test-time scaling 嗎？需要。它們的訓練本身就大量使用 test-time scaling：產生推理步驟、用 reward 做 RL、把正確的軌跡拿去訓練下一輪；測試時多取樣仍能探索解空間的不同部分。
    • 未來會不會只在訓練時多取樣，測試時只跑一次？這是希望的方向，讓模型第一次就答對、效率更高。但如果把模型訓練得太「尖銳」，只偏好單一答案，可能會失去思考的創意與多樣性，而那正是我們想保留的特質。

    課堂問答精選

    學生在課堂上提出的問題，往往正好打在觀念最容易混淆的地方。先自己想一下答案，再展開對照。

    訓練或測試 verifier 時，需要人即時參與嗎？

    不需要。人類只在一開始離線替每題寫一次標準答案。之後 generator 對每題產生 100 個解答，逐一和標準答案比對就能自動建立標籤。測試時 verifier 對候選排序、取最高分，再和標準答案比對來報告正確率。

    候選數超過 400 之後，正確率為什麼會下降，而不是持平？

    因為圖上畫的不是 coverage，而是整個系統挑出來的答案是否正確。候選越多，verifier 的精確度越吃緊：如果兩個解答分數非常接近、卻一對一錯，在 800 個候選中比在 400 個中更難分辨，所以正確率下降。

    資料量非常大時，fine-tuning 和 verification 會不會收斂成同一件事？

    資料量真的非常大時，兩者可能越來越像。但 verifier 有個好處：不需要去 fine-tune 基礎語言模型，不會把它過度特化到單一資料集或任務。Generator 可以保持通用，再由 verifier 引導。

    如果推理只寫「令分子為 x」，下一步就直接跳到「x = 14」，PRM 會給高分嗎？

    PRM 評分時不只看當前這一步，也會看題目與前面所有步驟。在 PRM800K 中，標籤是人類依前後文判斷的；人類看到跳過好幾步推理的「x = 14」會覺得不合理而給低分。

    真正要小心的是拿 PRM 去微調 generator：模型可能學會停止推理，只產生 PRM 喜歡的輸出。如果不訓練 generator，只用 prompt 讓它產生推理步驟、PRM 只負責評分，這個風險就小很多。若 PRM 的標籤不是人類產生的（例如 Math-Shepherd），這確實是一個要注意的地方。

    PRM 會不會反而有害？畢竟最後答案還是可能錯。

    很多新方法會把 PRM 和 ORM 結合，想同時拿到兩邊的好處。不過 PRM 的門檻值本身是超參數，系統會多一個要調的東西，複雜度增加。標註成本也不同：ORM 需要 k 個標籤，PRM 需要 k 乘上步數，而步數很難精確控制，論文也提到兩者很難公平比較。

    這裡的「多數投票」具體是怎麼做的？

    有 n 個樣本、沒有 reward model 可用時，看哪個最終答案出現最多次，就把它當成答案。只比對最終答案，不比對推理過程。

    能不能設計出鼓勵模型自我修正（self-correction）的 PRM？

    可以，但只獎勵「每一步都正確」不一定會逼出自我修正。一種做法是給模型一份 rubric 或規則集，讓它拿每一步去對照，當成額外的訊號；也可以讓模型使用工具，例如用 sympy 解方程式。透過工具、test-time scaling 與 agentic 的做法，都能替驗證引入更多監督訊號。

    算力固定時，應該多取樣 generator，還是多花在 verifier 上？

    講者認為這是很好的研究問題，論文中沒有直接回答。比較時的挑戰是公平性：ORM 和 PRM 最好來自同一份資料，才能 apples-to-apples 比較；拿自己訓練的 PRM 去比別人的 ORM，訓練資料的差異會干擾結論。

    為什麼 RL 訓練後，評估時只用 greedy decoding，不再調 temperature 多取樣？

    主表確實只比 greedy decoding。下一張投影片就是另一個設定：在 RL 模型之上，再對 256 個輸出做驗證，結果更好。講者補充：論文沒做的是從 RL 後的模型重跑整個流程（產生新標籤、訓練新 verifier），那會是有趣的實驗。

    Generator 與 verifier 用相同還是不同架構比較好？

    這是好的研究問題。一般來說，模型對自己產生的內容、自己的解讀方式比較「順」，勝過使用不同家族的模型；課程後面也會談到某些模型能從不同類別的 verifier 受益。但講者表示還沒看到專門比較 verifier 大小與家族組合的研究。

    12

    一頁總結

    1. Generation-verification gap：多取樣能讓 coverage 上升，但要有 verifier 把正確答案挑出來，收益才會兌現。
    2. Outcome verifier（2021）：以標準答案自動標註 100 個候選、訓練 verifier，測試時取最高分；資料夠多時勝過 fine-tuning。
    3. 候選不是越多越好：候選太多時，說服力強的錯誤答案更容易騙過 verifier，正確率會先升後降。
    4. ORM 對 PRM：PRM 逐步打分、分數相乘，較能抓到「過程錯、答案對」，也較能泛化，但人工標註昂貴。
    5. 自動標註：Math-Shepherd 以 rollout 的 hard／soft estimate 取代人工，訓練出的 PRM 勝過人工標註版本，還能當 PPO 的 reward。
    6. 集成弱驗證器：Weaver 以弱監督估計各 verifier 的可信度並加權，讓小模型接近大一級的模型，再蒸餾到 0.4B 以大幅降低成本。
